# FPS-R6A — Labyrinth architecture, rooms, and lighting

## Baseline and scope

- Repository: `ThuleGamesDev/Aether-Crawl-`
- Base branch: `main` at `b4c46318c3737385ec9e13c4f4e88c48ee839183` (merged PR #22 / R5C)
- Feature branch: `codex/maze-of-the-minotaur-fps-r6a`
- Save contract: Maze save version 4 remains unchanged. `architectureRooms` is optional, so earlier floor data needs no migration.
- New floor footprint: 23×23. The 12×12 recursive generator remains the default for legacy callers. Only the FPS world's new-floor path selects the architectural topology.
- Runtime boundary: `FPSGameRuntime` owns simulation. `WorldGeometry` and `SceneRenderer` own presentation. The tile grid remains authoritative for movement, enemies, interactions, line of sight, and projectile collision.
- No new package, network asset, hosted generator, or R6D1 Law content was added.

## Layout and gameplay placement

`services/labyrinthLayout.ts` creates a seeded 3×3 chamber topology. It combines 4–7 cell halls and galleries, crossings, rotundas, red pillared halls, 2–3 cell main passages, occasional one-cell passages, and loop routes. Pillars keep `TileType.WALL` and use a persisted decoration marker, so all existing collision and raycast queries block them without extending the tile enum.

`services/dungeonPlan.ts` still owns the existing gameplay room types and decisions. It places at least two combat rooms in distinct suitable chambers on each new floor, then assigns the existing Rest, Treasure, Shrine, Elite, Trap, Event, Locked, Secret, Ante-Chamber, and Boss nodes. It does not carve over existing floor to make a room. The Guardian arena is a seven-by-seven clear area with one corridor entrance; nearby chamber bounds keep the entrance from being bypassed around a corner.

`ArchitecturalRoom` metadata records `roomShape`, `combatSuitability`, `lightingTheme`, and `landmarkIds`. Its optional `roomArchetype` field is reserved for future content and is not populated by R6A. Floor data validation accepts old saves with no architecture list and validates metadata when present.

The spawner places ordinary floor enemies in the selected combat chambers, checks the full collision radius against the grid, and keeps them away from the player. Guardian candidates come from the clear arena and pass the same collision check. Pillar walls continue to block movement, raycasts, enemy line of sight, and projectiles through the existing grid rules.

## Art, lights, and map display

Decoration code `1` keeps its existing wall torch meaning. It now mounts on a cardinal wall face with a correctly oriented plane and a fixed vertical height. Oil bowls use the new floor code `7` and sit at floor height. Codes `8–10` identify pillars, fresco panels, and bull reliefs. The old tile map and its saved decoration codes are not rewritten.

Local assets are generated by `scripts/generate-maze-assets.py` and registered in `data/assetRegistry.ts`: a wall torch, fresco panel, and chthonic altar join the existing limestone, bronze, and regional prop set. Pillars use low-poly red limestone shafts with bronze caps and bases. Room lighting uses a maximum of six unshadowed point lights per floor. `SceneRenderer` updates only the existing light intensities, with no per-frame geometry or light allocation. Other surfaces use the existing nearest-neighbor pixel textures.

The legacy `Minimap` now derives grid dimensions from the map and fits non-square maps inside its canvas. Its cell and player-marker coordinates scale from the same transform.

## Copilot follow-up from R5C

The merged R5C review at [PR #22](https://github.com/ThuleGamesDev/Aether-Crawl-/pull/22#discussion_r4444846674) left two follow-up findings on the current base:

- `InputSystem.handoffToUi()` cleared touch state and pointer lock, but a touch pointer captured by the canvas could still block overlay events. The input system now tracks captured touch IDs, releases all active captures during handoff/focus clearing, handles `lostpointercapture`, and has a two-pointer regression.
- `calculateDerivedStats()` built item tags even when an equipped item had no affixes. It now skips that lookup for empty affix lists; derived values stay unchanged.
